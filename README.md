# 결 · SAKE CURATION — 사케 취향 큐레이션 시연

가상 브랜드 `결 · SAKE CURATION`의 상품 큐레이션 프로토타입입니다. 상품·가격·태그·재고는 모두 가상이며 실제 판매·주문·결제·회원 기능이 없습니다. 정적 파일만으로 동작하고 빌드가 필요 없습니다.

## 실행

```bash
python -m http.server 8795
# http://localhost:8795/
npm test   # node --test tests/*.test.mjs
```

ES 모듈이므로 `file://`이 아닌 로컬 서버로 여세요. Node 20 이상에서 테스트가 돌아갑니다. 의존성 설치 없음.

## 화면 흐름

1. 히어로: `오늘의 취향에, 한 병의 발견.` — Three.js로 절차 생성한 초록 유리병(포인터·스크롤 연동 회전). WebGL 컨텍스트는 히어로 캔버스 하나만 만들며, 첫 실제 렌더 뒤 자작 SVG 병과 `visibility`로 한 번에 교체(알파 혼합 없음). 생성 실패·성능 경고·컨텍스트 소실 시 SVG 병 유지.
2. 히어로 → 퀴즈 마스크 장면: 짙은 상록 지면 위 크림 ‘종이 라벨’ 면이 스크롤 진행(`--open` 0→1)에 따라 inset 마스크로 열려 퀴즈 섹션 지면이 됩니다. 마스크는 장식 레이어에만 걸리고 글자·버튼은 항상 위에 있어 잘리지 않습니다. JS 없음·`prefers-reduced-motion`에서는 열린 상태로 정적 완결.
3. 내 취향 찾기(`#quiz`): 예산 → 스타일 → 음식 3문항 → 결과 최대 3개 → 상세 `<dialog>` → 목록 복귀.
4. 컬렉션(`#collection`): A–E 5종, 이름·태그 검색과 스타일·음식 칩 필터. E는 품절 배지.
5. 큐레이션 이야기(`#story`): 6축(단맛/드라이/산미/감칠맛/바디/향) 설명.
6. 직원 개념 패널(`<details>`): 6종 전체(비노출 F 포함) 재고·상태 읽기 전용 샘플.

## 가상 데이터·규칙 (`core.mjs`)

| ID | 표시명 | 매장가 | 소매가 | 태그 | 맛 6축 | 재고/상태 |
|---|---|---:|---:|---|---|---|
| A | 가상 사케 A · 맑은 결 | 90,000 | 65,000 | 산뜻·해산물 | 2/4/3/2/2/3 | 4 · 판매중 |
| B | 가상 사케 B · 깊은 결 | 120,000 | 85,000 | 묵직·구이 | 2/4/2/5/5/2 | 3 · 판매중 |
| C | 가상 사케 C · 꽃의 결 | 100,000 | 70,000 | 향긋·해산물 | 4/2/3/2/2/5 | 2 · 판매중 |
| D | 가상 사케 D · 부드러운 결 | 80,000 | 55,000 | 산뜻·구이 | 3/3/2/3/3/3 | 5 · 판매중 |
| E | 가상 사케 E · 계절의 결 | 110,000 | 80,000 | 향긋·해산물 | 4/2/3/3/3/4 | 0 · 품절 |
| F | 가상 사케 F · 숨은 결 | 130,000 | 95,000 | 묵직·구이 | 2/5/2/4/4/2 | 2 · 비노출 |

- 가격 모드는 `매장가` / `소매가` 중 하나만 화면 전체(카드·히어로·결과·상세·직원 패널)에 표시. 헤더의 제어는 `시연용 가격 모드 · 직원 인증 미구현`이며 보안 수단이 아닙니다.
- 추천 후보 = 판매중 AND 재고>0 AND 선택 모드 가격 ≤ 예산. 스타일 일치 +3, 음식 일치 +2, 상관없음 0.
- 스타일/음식 중 하나라도 지정하면 점수 0은 제외. 동점은 ID 오름차순, 최대 3개, 적으면 실제 수만 표시.
- 둘 다 상관없음이면 `예산 안의 상품`(ID순 최대 3개)으로 표시하고 취향 일치로 말하지 않음.
- 검증 예: 매장/100,000/산뜻/해산물 → A5·D3·C2. 소매/70,000/향긋/해산물 → C5·A2(두 개). 매장/100,000/상관없음/상관없음 → A·C·D. 예산 50,000 → 빈 상태 + 조건 다시 선택. E·F는 추천 안 됨, F는 고객 목록에도 없음.
- 모드 전환 시 예산 적격·결과 순서·열린 상세 가격을 즉시 재계산(캐시 없음).
- 결과 캡션 `가상 상품·가격 · 규칙 기반 추천 예시 · 실제 구매 불가`.

## 제외 기능(미구현)

실제 판매·주문·결제·장바구니, 회원·직원 인증, 재고 동기화·POS·QR 생성, 외부 링크, 저장소(localStorage 포함)·네트워크·분석 스크립트, 서버 렌더링. 상태는 메모리에만 있고 새로고침 시 초기화됩니다. 제조사·산지·도수·용량 등 실제 사실은 다루지 않으며 미제공 필드는 `자료 확인 전`으로 표시합니다.

- `tests/core.test.mjs` 규칙·데이터·상태, `tests/structure.test.mjs` 경계·자원·접근성 계약

- 3D: `vendor/three.module.js`, `vendor/three.core.js` (r180, MIT, `vendor/THREE_LICENSE.txt`). 외부 HDRI·텍스처·모델 없이 평면 발광체로 PMREM 환경을 만듭니다.

## 검증 범위

`npm test`(Node 내장 테스트 33건)가 소스 계약으로 확인하는 범위: 규칙·정답 예시, 외부 로드 0, 단일 WebGL 컨텍스트·visibility 교체, 등장 모션은 translate 전용 0.7~0.8s(JS 없이도 모든 글자 표시), 마스크 장면이 장식 레이어에만 적용, 섹션 상하 여백 `clamp(96px, 60px + 7vw, 168px)`(1440 약 161px·390 96px), CSS·SVG 글자 12px 미만 0, 주요 컨트롤 44px, 다이얼로그 표면 불투명(transform 전환, backdrop 분리). 브라우저 실측(320/390/768/1440 넘침·대비 4.5:1·전환 중간 프레임·키보드·Escape·`inert`)은 별도 QA에서 확인합니다.
